# Deny unsupported governed writes outside the fleet

The shared gate denies every unsupported command observation when the caller directory is not a fleet repository and the command names no directory with `git -C`. Fleet callers already receive the same denial for these unsupported shapes. This includes unsupported commands without a parsed write, such as an unterminated Bash heredoc, a Git alias, or a repository-environment prefix. It also includes read-only commands using unmodeled Git global options such as `--git-dir=` or `--work-tree=`. Only unsupported observations reaching this non-fleet path without an observed command directory change from pass to deny. Other decision paths are unchanged. Recognized and ambiguous writes outside the fleet may still pass under the existing scope; this proposal is not a general write-denial rule. This does not establish that every write is denied or restrict ordinary local reads generally. It does not change command recognition, access grants, or installation state.
